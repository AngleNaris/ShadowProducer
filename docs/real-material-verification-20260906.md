## 问题与限制

1. **ProRes 资源库快速预览没有可解码画面。** 双击 MOV 后直接请求原始 `/content`，浏览器 duration=8、readyState=4，但 videoWidth/videoHeight=0、已解码视频字节=0。审片页使用转码代理则可播放。定位：`apps/web/src/components/resource-library.tsx:3930`，预览视频 src 使用原文件而非已有代理。
2. **MP3 快速预览缺少播放器。** 双击旁白后弹窗仅显示“暂无预览”，不能试听。音频存储、下载和时长提取通过不等于音频预览通过。定位：同文件 `:3928`，只有视频播放器分支，其他类型进入 AssetPreview。
3. **播放结束后添加对比，界面时间与主视频位置不一致。** v2 播放至 8 秒结尾后添加 B=v1，界面显示 00:00.000；点击播放，读取到 A=8 秒、B=3.458 秒。`review-studio.tsx:1875` 的 selectCompareFile 只重置 React time，没有重置主视频 currentTime；togglePlayback 在 `:1893` 排除已结束主视频。本轮未进行帧精度同步验收。
4. **100 MiB 上传上限阻断真实成片导入。** `7.导出\破天一剑动画预览0117.mp4` 为 372817184 字节，UI 明确返回“当前开发上传单文件上限为 100 MB”。目录内四个导出成片约 369–819 百万字节，均超过当前限制。未修改限制或裁剪原片绕过验收。
5. **空文件提示不具体。** 真实零字节 `1.原始素材\3\A003C0053_250106_7H2970_Proxy_clip.mp4` 正确被拒绝，但只提示“请求参数不符合契约”。
6. **选中文件夹后导入仍进入收件箱。** 选择新建测试文件夹上传，素材仍写入收件箱并关联第一个项目；代码 `resource-library.tsx:1321` 的 importFiles 显式使用 inboxId、projects[0]。属于当前实现的工作流落差，未证明为数据损坏。只有 PNG 本轮随后通过 UI 移至测试文件夹，其余四项保留在收件箱。

控制台出现预期的空文件/超限上传错误；刷新资源库后有 3 条 Next 图片 LCP 提示。不能宣称整个会话零错误或零警告。

### 生产应用步骤与边界

1. 备份数据库并保留当前应用/worker 版本与旧衍生对象；暂停旧媒体 worker，不能让旧 worker 消费新版重建任务。
2. 部署匹配的 Web/API/worker 代码。确认 FFmpeg、ffprobe 可执行，FFmpeg 具备 libx264、AAC、libwebp 编码能力。
3. 将生产既有 `ASSET_MAX_UPLOAD_BYTES` 显式更新为 `2147483648`（2 GiB），否则原有 100 MiB 环境覆盖值仍生效；核对对象存储 CORS、分片上传、代理网络配置。
4. 通过既有迁移流程执行 `migrations/079_display_previews.sql`，再启动新版 `pnpm --filter @shadowproducer/api media:worker`。本地已应用，四项旧媒体重新排队，连同新增成片共五项处理任务均成功。
5. 复核任务状态、错误日志及三类媒体的实际展示地址、解码/播放、拖动定位与生产受限带宽表现，再完成生产签收。

迁移只重建有效素材中已完成的旧衍生文件；不会重置在途或失败任务，也不自动处理已归档素材。已有失败任务需定位后按现有重试流程处理。衍生文件重建期间预览暂不可用，不会用原文件兜底。

回滚优先暂停新版 worker、保留已生成衍生文件和强制预览访问策略，修复编码问题后重试。迁移没有删除原文件或变更表结构；如需完整版本/数据库回滚，使用上线前备份，并明确旧版本会重新引入本次修复的问题，不能视为满足强制转码要求。

目前采用单档视频代理，不是自适应多码率 HLS；极低带宽仍可能缓冲。未实际部署生产、未完成跨浏览器长片听审，前述完整业务功能验收边界仍然适用。
