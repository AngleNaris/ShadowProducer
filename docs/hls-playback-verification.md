# HLS 播放验证记录

验证日期：2026-09-06。范围是本地 ShadowProducer 的媒体转码、播放与访问控制，不包含生产部署、真实 AI 调用或邮件发送。

## 已实现

共享 Video.js 8 播放器接入资源预览、内部审片、客户审片与公开作品集。视频和音频提供手动质量选择以及自动自适应码率（ABR）。后端复用现有转码队列、对象存储和权限服务，不新增媒体基础设施。

- 视频生成最高 360p/500k、720p/1500k、1080p/3000k 的 H.264 档位，不放大小尺寸原片；音轨为 AAC 96k。
- 音频生成 AAC 64/128/192k 三档，48 kHz 双声道。
- 使用约 4 秒对齐的 fMP4 HLS 点播分片；图片沿用 WebP 预览。
- 菜单显示主清单声明的带宽需求，含音轨与 10% 余量，因此音频显示约 70/141/211 kbps，而非编码器目标值。
- 原文件保留用于下载。预览不回退到原文件；历史单档转码在重建完成前仍可播放。

ABR 根据网络和缓冲状态选择已经编码好的档位，并不是实时改变编码器码率。已缓冲画面会延迟可见的清晰度变化；不承诺瞬时切换、帧级双路同步、直播或低延迟直播。

## 修复的问题

- Windows FFmpeg 将初始化分片写入进程工作目录，导致上传后的 HLS 无法解码。转码现指定包目录作为工作目录，并校验初始化分片存在。
- 转码任务增加租约及尝试次数校验，过期 worker 不能覆盖新 worker 的处理结果。
- Video.js 容器类名修正，避免尺寸和自适应清晰度判断失真。
- 内部及客户审片的 B 路在异步就绪时接续当前时间与播放状态，避免用户先点击播放后 B 路停在零秒。
- 客户审片按真实播放结果更新按钮状态，不再将失败的播放请求显示为播放中。

## 发布与回滚

每个清单和分片入口均验证访问范围。分片使用 60 秒有效的签名重定向，因此已经签发的地址存在至多约 60 秒撤销窗口；已下载缓冲无法收回。清单拒绝外部地址和越界路径，存储桶保持私有。

发布时停止旧媒体 worker，备份资产预览指针与任务状态，安装锁定依赖并部署匹配的 API、Web、worker。执行 `pnpm db:migrate`，迁移 080 将已有已完成的音视频加入重建队列；观察队列完成后，再执行目标环境浏览器播放、跳转、切档与权限检查。

新 HLS 包使用不可变唯一目录，成功后才切换数据库指针。回滚时停止新 worker，恢复备份的指针与任务状态并切回匹配旧版本；保留历史转码文件和全部原文件。迁移 080 不包含破坏性 Schema 修改。
